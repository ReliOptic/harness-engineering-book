# DR-3.2 CLI-Anything HARNESS Summary

## 대상 중심적(Target-Centric) 패러다임: HARNESS.md의 하네스 정의
- CLI-Anything 프로젝트는 인간 중심의 복잡한 GUI 소프트웨어를 에이전트가 직접 제어할 수 있는 명령줄(CLI) 기반의 '에이전트 네이티브' 인터페이스로 변환함.
- 하네스의 6대 속성: 구조화 및 결합성, 경량/범용성, 자기 서술성(`--help` 동적 학습), 입증된 신뢰성, 에이전트 최우선(엄격한 JSON 출력 강제), 결정론적 작동.

## 아키텍처 및 구현 원칙: 7단계 자율 생성 파이프라인과 비파괴적 진화
- 에이전트가 소프트웨어를 직접 분석하여 도구를 생성하는 7단계 파이프라인(분석, 설계, 구현, 테스트 계획, 테스트 작성, 문서화, 배포)을 규정함.
- REPL 및 Undo/Redo 로직을 포함한 상태 모델 기반 설계와, `/cli-anything:refine`을 통한 점진적, 비파괴적 기능 커버리지 확장을 지원함.

## 검증 체계와 컨텍스트 엔트로피 제어를 위한 테스트 방법론
- 철저한 테스트 주도 개발(TDD)을 채택하여 `TEST.md` 마스터 문서를 통해 단위 테스트와 단대단(E2E) 상태 전이를 검증함.
- 에이전트가 장시간 작동하며 목적을 망각하는 '컨텍스트 엔트로피' 및 환각 현상을 텍스트화된 테스트 이력을 통해 기계적으로 차단하고 닻(Anchor) 역할을 함.

## 패러다임의 충돌: 기존 하네스 정의와의 비교 분석
- 기존 하네스(예: Everything Claude Code)가 '에이전트를 감싸 인지/메모리를 보조하는 런타임'에 집중했다면, CLI-Anything은 '대상 환경(소프트웨어)을 감싸 에이전트 친화적으로 깎아내는 어댑터 인터페이스'로 하네스를 재정의함.
- 이를 통해 에이전트의 컨텍스트 유지 부담을 덜고 경량 모델로도 높은 신뢰성을 달성할 수 있음.

## 구현상의 과제와 생태계 확장성
- 특정 환경을 암시하는 하드코딩된 절대 경로(`/root/cli-anything/`)로 인한 이식성 한계와, 각 에이전트 프레임워크별 설치 파편화 문제를 극복해야 하는 과제가 존재함.

## 결론 및 거시적 시사점
- 환경 조작 인터페이스를 결정론적인 CLI+JSON 형태로 개조함으로써, 복잡한 시스템들을 인간 개입 없이 연결하는 초자동화(Hyperautomation) 시대의 새로운 소프트웨어 상호작용 표준을 수립함.
