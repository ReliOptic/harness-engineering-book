# DR-3.4 Ontology as Agent Memory Structure Summary

## 1. Agent에서 Ontology란 무엇인가
- 에이전트가 활동하는 도메인 내의 개체(Entity), 관계, 제약 조건을 명시적으로 정의한 구조화된 스키마. 확률론적 LLM이 일관성 있게 작동하도록 강제하는 필수 규칙집임.

## 2. 기존 RAG vs. Ontology RAG — 무엇이 다른가
- 일반 RAG나 Graph RAG가 텍스트 유사도 기반으로 지식을 '발견'한다면, Ontology RAG는 사전 정의된 스키마(제약)를 통과한 데이터만 지식 그래프에 편입시킴(제약 우선). 하네스의 행동 통제 철학과 가장 잘 부합함.

## 3. 주요 CLI 도구 현황 (2025-2026)
- **Cognee CLI:** 지식 그래프를 우선 구축 후 온톨로지를 주입하며, MCP 서버를 통해 에이전트의 영구 메모리로 통합됨.
- **TrustGraph CLI:** "Context as Code"를 표방하며 OWL 기반 온톨로지 RAG 플로우와 실시간 스트리밍을 제공함.
- **LobeHub / OntoGuard:** 메모리 변형(mutation)이 일어나기 전 반드시 스키마 검증(validation)을 통과하도록 강제하는 시맨틱 방화벽 역할 수행.

## 4. Ontology와 Harness의 교차점
- 하네스가 에이전트 행동의 '경계'를 제어한다면, 온톨로지는 그 경계를 기술하는 '의미론적 언어'임. 메모리 보호, 권한 제어, 롤백을 위한 스키마 제약 조건으로 작용.

## 5 & 6. 인프라 배포 및 다중 에이전트 시스템의 공유 언어
- 전통적인 YAML 기반 IaC를 대체하는 Ontology-driven IaC로 진화 중.
- 다중 에이전트 환경에서 각 에이전트가 상이한 맥락에서도 정보의 의미(Context)를 잃지 않고 교환할 수 있게 하는 필수적인 '공유 언어'임.

## 7. 아직 해결되지 않은 문제들
- 실제 운영 데이터와 스키마가 어긋나는 Ontology drift 현상, 초기 구축(Cold start) 비용, 엄격성과 유연성 간의 트레이드오프 문제, 표준 벤치마크 부재 등.

## 9. Ontology와 Agent-2 전환: 핵심 연결 논증
- 1세대(Agent-1)가 외부 하네스에 의해 온톨로지 검증을 받았다면, 스스로 복구하고 학습하는 차세대(Agent-2, Self-immune) 시스템은 온톨로지를 '건강한 상태의 기준점'으로서 내부에 내재화함.
- 구조화된 기억은 지속 학습의 전제 조건이며, Ontology drift를 문제(오류)가 아닌 자기 교정(Self-correct)을 위한 '신호'로 수용하여 진화함.
