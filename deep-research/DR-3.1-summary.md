# DR-3.1 Agent System Terminology Summary

## 1. 서론: 모델 중심주의의 종언과 인프라스트럭처 패러다임의 부상
- 대규모 언어 모델(LLM)의 단순 크기 확장에서 벗어나, 에이전트의 신뢰성과 안전을 보장하기 위한 시스템 아키텍처(가드레일, 스캐폴딩, 하네스, 오케스트레이션) 구축으로 엔지니어링의 핵심 과제가 이동함.

## 2. Guardrails (가드레일): 정적 윤리 필터에서 동적 런타임 제어 메커니즘으로의 진화
- 규제 강화와 OWASP LLM 보안 취약점(프롬프트 인젝션, 과도한 권한 행사 등)에 대응하기 위해 단순 필터링을 넘은 런타임 통제 메커니즘으로 진화.
- 프롬프트, 스키마, 런타임 승인, 도구 유효성, 생명주기 훅의 5단계 심층 방어(Defense-in-Depth) 구조로 설계되어 에이전트의 일탈을 원천 차단함.

## 3. Scaffolding (스캐폴딩): 모델을 목적 지향적 에이전트로 조립하는 구조적 뼈대
- 에이전트가 첫 번째 프롬프트를 받기 전, 시스템 프롬프트 조립, 도구 스키마 구성, 메모리 구조를 설정하는 '초기 조립(Assembly)' 단계와 그 골격.
- 에이전트의 인지적 제어 루프를 결정하며, 대화가 길어질 때 발생하는 컨텍스트 붕괴를 막기 위한 메모리 유지 및 동적 토큰 압축(Compaction) 기능을 포함함.

## 4. Harness (하네스): 런타임 오케스트레이션과 검증의 결정적 인프라
- 스캐폴딩이 정적 구조라면, 하네스는 실행 시점(Runtime)에서 에이전트의 궤적을 감싸고 도구 사용과 오류를 교정하는 역동적 제어 인프라임.
- 에이전트의 빠른 코드/작업 생성 속도에 대응하기 위해 인간을 대신하여 결정론적 시뮬레이션, 명시적 불변성 강제, 관측성 피드백 등을 자동 수행하는 '하네스 우선(Harness-First)' 검증 파이프라인이 필수화됨.

## 5. Orchestration Layer (오케스트레이션 계층): 다중 에이전트 체제의 중앙 지휘 평면
- 단일 에이전트의 도메인 과부하와 보안 위험을 피하기 위해, 전문 에이전트들(MAS)을 지휘하고 작업을 분배하는 중앙 제어 시스템.
- 분산 추적 데이터(Observability)와 지식 그래프를 바탕으로 최적의 에이전트를 동적 할당하여 의사 결정 속도와 처리량을 획기적으로 향상시킴.

## 6. 오케스트레이션의 확장: 상호운용성을 위한 개방형 통신 프로토콜 (MCP & A2A)
- 벤더 사일로를 극복하기 위해 Model Context Protocol(MCP)을 도입하여 외부 지식/도구와의 연결을 표준화함.
- A2A(Agent-to-Agent) 프로토콜을 통해 이질적인 에이전트 간의 자율적 협력, 상태 관리, 보안 통신(mTLS)을 위한 공용어를 확립함.

## 7. 심층 통찰 및 결론
- AI 산업의 진정한 경쟁 우위(Moat)는 파운데이션 모델 그 자체가 아니라, 모델을 런타임에 통제하고 검증하며 협업시키는 '인프라스트럭처(스캐폴딩, 하네스, 가드레일, 오케스트레이션)' 설계 역량으로 완전히 이동하였음.
