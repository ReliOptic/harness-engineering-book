# Ch.1 — 지금 무슨 일이 일어나고 있는가

2026년 3월 기준으로, agent를 실제 운영 환경에 배포하려는 사람이 마주치는 가장 큰 결정은 모델이 아니라 product surface다. 에이전트가 어떤 인터페이스 위에서 작동할 것인가에 대한 생태계의 합의는 아직 이루어지지 않았다. 기존의 Web UI가 인간을 위해 설계되었다면, 현재 시장은 에이전트를 일차적 사용자로 상정한 표면을 탐색하는 중이다. 컴퓨팅 자원의 제약은 이 표면의 한계를 더 선명하게 드러낸다. 공유 vCPU와 1~2GB RAM을 제공하는 클라우드 무료 티어 환경에서 에이전트를 운영할 때, 자원이 충분한 환경에서는 지연되어 나타날 CPU 포화나 메모리 누적 현상이 수 시간 이내에 시스템의 1차 병목으로 작용하는 것을 필자는 반복적으로 관찰했다. 이 기록은 2026년 상반기 생태계의 스냅샷이다. 에이전트 시스템이 고도화되어 실패 메커니즘이 추상화의 장막 뒤로 숨기 전에, 구조적 취약점이 가장 투명하게 노출되는 지금의 조건들을 명확히 규정하기 위함이다.

OpenClaw는 60일 만에 25만 개 이상의 GitHub Star를 획득하며 대규모 언어 모델 래퍼에서 자율형 에이전트 인프라스트럭처로의 전환을 주도했다. 단일 프로세스 위에서 추론, 메모리, 실행 계층을 모듈화하여 도구 호출과 컨텍스트의 지속성을 결합한 에이전트 친화적 경험의 초기 형태를 제시했다. 그러나 상시 가동되는 모놀리식 아키텍처와 넓은 권한 부여는 보안 모델의 치명적 결함을 노출했다. 로컬 에이전트에 대한 공격 모델을 분석한 벤치마크(arXiv:2602.08412)에서 나타나듯, 메모리 경계가 없는 상태에서의 장기 실행은 데이터 유출 및 시스템 탈취 등의 위협을 구조적으로 내포한다. 필자가 이 단일 프로세스 아키텍처 위에서 컨텍스트 객체가 무제한으로 누적될 때 관찰한 것은 가비지 컬렉션 주기가 CPU를 점유하여 시스템 전체를 마비시키는 현상이었다. 이는 단순한 버그가 아니라, 메모리 경계와 자원 통제 구조가 결여된 모놀리식 설계가 도달할 수밖에 없는 필연적인 결과였다.

OpenClaw의 구조적 결함은 생태계를 초경량화, 메모리 격리, 그리고 다중 에이전트 오케스트레이션을 지향하는 마이크로 런타임으로 분열시켰다. 엣지 환경에 최적화된 Nanobot이나 단일 바이너리 격리를 실현한 NullClaw는 극단적 미니멀리즘으로 대응했다. 초경량 에이전트 런타임 중 하나는 보안 감사 과정에서 블랙리스트 기반 원격 코드 실행 방어의 근본적 한계를 드러냈으며, 이는 수학적 메모리 안전성을 제공하는 Rust 기반 프레임워크들의 부상으로 이어졌다. 트레이트 기반의 ZeroClaw, 샌드박스를 강제하는 Moltis, 그리고 WASM과 암호화를 통해 기밀성을 확보한 IronClaw가 이 영역을 채우고 있다. 거대한 컨텍스트 윈도우에 의존하던 기억 구조 또한 memU와 같은 지식 그래프 기반 메모리로 전환되면서, 단순한 텍스트 누적을 넘어 능동적으로 인텐트를 예측하는 체계로 진화하고 있다.

인간 중심의 UI를 넘어 에이전트가 화면을 조작하고 네이티브 UI를 동적으로 생성하는 A2UI와 GUI 자동화 모델(arXiv:2505.00684, arXiv:2505.12493)이 등장했다. 초저지연 음성 모델은 콜센터 등의 노동집약적 인프라를 대체하며 에이전트 스케일의 파급력을 입증하고 있다. 그러나 모델과 도구 간의 범용 표준으로 설계된 Model Context Protocol(MCP)은 그 무거움으로 인해 한계를 드러냈다. 수많은 스키마를 모델에 주입하여 발생하는 막대한 컨텍스트 낭비와 다중 도구 연결 시의 동시성 실패(arXiv:2603.05637)는 MCP의 오버엔지니어링 문제를 부각시켰다. 무거운 GUI와 복잡한 프로토콜의 반작용으로 시장은 LLM과 터미널이 직접 결합된 에이전틱 CLI로 강하게 회귀하고 있다. CLI는 운영체제 수준에서 네이티브로 실행되어 리소스 소모가 적고, 확정적인 시스템 계약을 준수하는 환경이다. 최근 OpenAI의 하네스 엔지니어링 연구가 코덱스(Codex)와 터미널의 결합을 통해 자율적 에이전트의 신뢰도를 높인 사례는 이러한 회귀의 기술적 타당성을 뒷받침한다. 에이전트 경제는 소프트웨어 라이선스가 아닌 결과 기반으로 재편되고 있으며, 궁극적으로는 인간의 개입 없이 신원 인증과 결제(arXiv:2509.04979)를 자율적으로 수행하는 에이전트 간 네트워크 환경으로 수렴할 것이다.

OpenClaw 위에 다중 에이전트 환경을 구축했을 때, 1차 병목은 모델의 추론 능력이 아니라 컴퓨팅 자원의 경합이었다. CPU 사용률이 100%에 고착되고 시스템 응답이 중단되는 현상을 초기에는 모델이 컨텍스트를 제대로 처리하지 못하는 증상으로 오진했다. 노드 힙 메모리 누적에 의한 가비지 컬렉션 점유, 부하 증가에 따른 독립 타이머들의 동시 실행, 공유 컨텍스트에서의 블로킹 현상은 모두 단일 프로세스 위에서 제어 장치 없이 실행될 때 발생하는 구조적 실패였다. 오케스트레이터 역할을 하는 상위 모델의 태스크 분해 오류가 하류 전체로 전파되어 치명적인 품질 저하를 일으키는 비대칭적 오류 전파 구조 또한 동일한 환경에서 나타났다. 에이전트가 멈추는 것이 아니라 잘못된 방향으로 계속 진행하는 이 실패 패턴은, 시스템을 감지하고 통제할 수 있는 물리적 레이어를 요구한다.

에이전트 시스템의 성능과 실패를 규명하기 위해 이 책은 모델, 하네스, 표면, 운영자 개입, 연산이라는 5변수 프레임워크를 적용한다. 모델의 성능과 시스템 운영 구조라는 이원론적 관점으로는 두 요소가 모두 최적화된 상태에서 컴퓨팅 자원의 한계가 새로운 1차 병목으로 떠오르는 현상을 설명할 수 없었다. 모델을 교체하는 것만으로는 실패의 재현 조건을 바꿀 수 없었으며, 각 변수는 독립적으로 작용하는 동시에 상호 결합하여 시스템의 임계점을 결정한다. 모델 변수는 단일 호출 품질을 평가하는 기존의 벤치마크나 벤더 티어로 측정하기 어렵다. 에이전트는 연쇄적인 다단계 추론과 도구 호출을 수행하며 초기 오류가 하류에서 증폭되는 구조에 놓여 있다. 이후 챕터는 다단계 체인에서의 오류 누적 저항성을 측정하기 위한 ARCC(Agent-Relevant Capability Composite)라는 새로운 기준을 통해 벤치마크와 실제 운영 가능성 사이의 경계를 탐색할 것이다.

현재 시장에 배포된 대부분의 시스템은 Agent-1 단계에 머물러 있다. 외부 도구를 호출하고 결과를 다음 단계의 입력으로 사용하는 능력은 크게 발전했지만, 에이전트 스스로 자신의 역량 한계나 상태를 인지하지 못한다. 능력이 부족해서가 아니라 자가 모니터링 체계가 없기 때문에 임계점 근접을 감지하지 못하고, 외부의 하네스와 운영자 개입 없이는 장기 실행을 보장할 수 없다. Agent-2로의 전환은 에이전트 내부에 ARCC 자가 모니터링과 자기 주도적 복구 루프, 즉 자기 면역 시스템을 내재화하는 과정이다. 이 자가 모니터링 자체가 모델의 추론 자원을 소비하므로, 시스템이 무너지는 그 순간에 자가 진단 기능 또한 신뢰성을 잃게 되는 재귀적 구조가 발생한다. 이 책의 실험이 측정하려는 것은 정확히 이 Agent-1과 Agent-2 사이의 경계다.

칩 후옌의 AI Engineering(2025)은 모델 훈련과 비즈니스 적용을 분리하여 생성형 AI 애플리케이션 구축의 파운데이션을 체계화했다. 그 연구는 프롬프트 엔지니어링부터 RAG, 파인튜닝, 평가 프레임워크에 이르기까지 애플리케이션 계층이 어떻게 구성되어야 하는지를 보여준다. 이 책은 그 지도가 묘사하는 애플리케이션 계층의 바로 위에서 논의를 이어간다. 에이전트가 단기적 대화를 넘어 다단계 계획과 실행의 순환 구조를 장기간 자율적으로 유지할 때 발생하는 확률론적 모델의 연쇄적 오류, 지연 시간 증가, 프롬프트 표류 현상은 기존 애플리케이션 프레임워크로는 통제하기 어렵다. 커뮤니티가 모놀리식 구조에서 다중 에이전트 오케스트레이션으로 이동하고, 평가 파이프라인에서 AI 심판의 구조적 편향과 마주하는 현실이 이를 뒷받침한다. 이 챕터가 기록한 관찰들은 이후 챕터들이 측정하게 될 문제의 윤곽이며, 하네스 엔지니어링이 개입해야 할 좌표를 정의한다.
최근 GitHub 생태계의 스냅샷을 살펴보면, 이러한 과도기적 도전들이 어떻게 구체적인 프로젝트들로 발현되고 있는지 확인할 수 있다. OpenClaw의 초기 성공을 바탕으로, 이를 보완하거나 대체하려는 다양한 시도들이 등장했다. 예를 들어, 보안과 경량화에 집중한 Nanobot은 단 4,000줄의 코드로 MCP 네이티브 호스트 역할을 수행하며 빠르게 확산되었고, IronClaw는 기밀성이 요구되는 CRM 워크플로우에 특화된 샌드박스 환경을 구축했다. 반면, 에이전트 간의 상호작용과 자율성을 극대화하기 위한 연구도 활발히 진행 중이다. Internet 3.0(arXiv:2509.04979)이 제안하는 AgentRank-UC 알고리즘이나 Microsoft의 에이전트 내부 인증 모델은 에이전트 간의 신뢰와 권한을 관리하기 위한 필수적인 인프라로 자리잡고 있다.

결론적으로, 2026년 현재의 에이전트 생태계는 단일 모델의 성능 경쟁을 넘어 시스템적 한계와 구조적 결함을 통제하기 위한 다층적 모색의 시기이다. 하네스 엔지니어링은 이러한 과도기에서 에이전트가 안전하고 지속 가능하게 작동할 수 있는 '운영적 포위망(Operational Envelope)'을 설계하는 필수적인 학문이자 실무다. 이 책이 제시하는 5변수 프레임워크와 실험적 관찰들은, 에이전트의 잠재력을 현실의 제약 속에서 안전하게 이끌어내기 위한 첫 번째 이정표가 될 것이다.
