# 케이스 스터디: OpenClaw CPU 100% 인시던트 — 단일 에이전트 한계

**소스:** 저자 직접 관찰 (OpenClaw 운용, 2025). 보조: DR-1.1 (OpenClaw 아키텍처 분석)
**챕터 참조:** Ch.1 섹션 2
**형식:** 단일 에이전트 harness=None 조건에서의 5변수 분석. 서사 없음.

---

## 1. 시스템 사양

| 항목 | 값 |
|------|-----|
| 런타임 | Node.js (V8), 단일 프로세스 |
| 메모리 관리 | In-process Dict (외부 DB 없음) |
| 도구 목록 | 웹 검색, 파일 읽기/쓰기, Telegram 메시지 전송 |
| 인터페이스 | CLI 우선 |
| 백그라운드 태스크 | 로그 정리, 메모리 요약, 상태 체크 (각자 독립 타이머 보유) |
| 모델 | Claude API (단일 프로바이더) |
| harness | 없음 (메모리 경계, 자원 모니터링, 중앙 스케줄러 부재) |
| Watchdog | 없음 |

---

## 2. 관찰된 증상

| 항목 | 관찰값 |
|------|--------|
| CPU 사용률 | 100% 고착 (정상 응답 불가) |
| 재현 패턴 | 강제 종료(SIGKILL) 후 재시작 시 수십 초 이내 재발 |
| 로그 상태 | 명확한 오류 없음 (unhandled exception 미기록) |
| 첫 발생 시점 | 연속 운용 6–12시간 이후 |
| 복구 방법 | 수동 재시작. 자동 복구 메커니즘 없음. |

---

## 3. 실패 메커니즘 3개

### M1: GC Death Spiral

| 항목 | 내용 |
|------|------|
| 조건 | 대용량 컨텍스트 객체 힙 누적 (장기 실행 + in-process 메모리 관리) |
| 메커니즘 | GC CPU 점유 증가 → 처리 지연 → 메모리 추가 누적 → GC 빈도 증가 (양성 피드백) |
| 재현성 | 장기 실행(>6시간) + 컨텍스트 객체 크기 > 수백 MB 조건에서 재현 |

### M2: Cron Pile-up

| 항목 | 내용 |
|------|------|
| 조건 | 3개 이상 백그라운드 태스크가 각자 독립 타이머 보유 + 시스템 부하 >70% |
| 메커니즘 | 부하 시 타이머 실행 지연 → 지연된 태스크 동시 실행 → CPU 포화 |
| 재현성 | 시스템 부하 상승 시점(예: 대형 태스크 처리 중)에 규칙적으로 재현 |

### M3: Context Contamination

| 항목 | 내용 |
|------|------|
| 조건 | 모든 태스크가 단일 프로세스 내 공유 컨텍스트 참조 + 장기 태스크 실행 중 신규 요청 |
| 메커니즘 | 장기 태스크 hang → 공유 컨텍스트 잠김 → 전체 응답 루프 블록 |
| 재현성 | 30초 이상 소요 태스크 + 동시 요청 유입 조건에서 재현 |

## 4. 5변수 진단

| 변수 | 상태 | 병목 기여 |
|------|------|----------|
| 모델 | Claude (고성능 단일 모델) | 병목 아님. 모델 교체로 M1–M3 해결 불가. |
| **harness** | **없음 (메모리 경계, 자원 모니터링, 스케줄러 중앙화 전무)** | **1차 병목. M1/M2/M3 세 메커니즘의 공통 전제 조건.** |
| surface | CLI | 2차 기여. 단일 프로세스 CLI 구조가 격리 없는 공유 컨텍스트를 허용. |
| intervention | 없음 (Watchdog, 자동 복구 없음) | 2차 기여. 장애 발생 후 수동 대응만 가능. |
| compute | 제한 없음 (RSS/CPU 상한 없음) | 2차 기여. 자원 소진 가속. |

**1차 병목 판정: `harness=None`**

M1은 메모리 경계(harness 기능)로 차단 가능. M2는 중앙 스케줄러(harness 기능)로 차단 가능. M3는 프로세스 격리(harness 기능)로 차단 가능. 세 메커니즘 모두 harness 없이는 모델 수준 또는 코드 수준 수정으로 해결 불가.

## 5. 단일 에이전트로 충분한 조건

이 케이스가 성립하지 않는 조건 — 즉 harness 없는 단일 에이전트가 허용 범위 내에서 작동하는 조건:

| 조건 | 근거 |
|------|------|
| 태스크 수명 < 5분 | GC Death Spiral 발생 시간 미달 |
| 동시 요청 없음 | Context Contamination 조건 미충족 |
| 백그라운드 태스크 0–2개, 수동 트리거 | Cron Pile-up 조건 미충족 |
| 컨텍스트 크기 < 5,000 토큰 | 힙 누적 속도 낮음 |
| 운용 시간 < 12시간 연속 | 메모리 누적 한계 미도달 |

**요약:** 단발성 태스크, 짧은 컨텍스트, 낮은 동시성 환경에서는 단일 에이전트 harness=None으로 충분. 이 케이스는 장기 운용 + 복수 백그라운드 태스크 조합 환경에 한정된 관찰.
