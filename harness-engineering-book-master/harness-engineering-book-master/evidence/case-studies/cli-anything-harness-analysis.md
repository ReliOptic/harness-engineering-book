## 1. CLI-Anything HARNESS.md 방법론 요약

**설계 팀:** HKUDS (홍콩대학교 데이터사이언스 연구소). 이 책의 저자와 독립.
**목표:** 기존 GUI 소프트웨어(GIMP, Blender, LibreOffice 등)를 에이전트가 직접 제어 가능한 CLI 형태로 래핑.
**핵심 명명:** "에이전트와 소프트웨어 사이의 양방향 어댑터 계층(Bi-directional adapter layer)."

### 정의된 harness의 6 속성

| 속성 | 구현 메커니즘 | 목적 |
|------|-------------|------|
| 구조화 및 결합성 | 단위 명령어 모듈화 + Unix 파이프라인 연계 | 에이전트 CoT와 실행 체인 직접 매핑 |
| 경량성 및 범용성 | 비침투적 CLI 래퍼 (타겟 소프트웨어 바이너리 비수정) | 프레임워크 종속성 제거 |
| 자기 서술성 | `--help` 플래그로 런타임 도움말 자동 생성 | 에이전트 제로샷 도구 발견, 프롬프트 토큰 절약 |
| 에이전트 최우선 설계 | 모든 실행 결과를 엄격한 구조의 JSON 출력 | 파싱 모호성 제거, 환각 차단 |
| 결정론적 신뢰성 | 상태 모델 기반 예측 가능한 명령어 실행 | 확률적 LLM의 한계를 실행 레이어에서 보완 |
| 복원력 | REPL 모드 + Undo/Redo 로직 harness 레벨 강제 | 에이전트 오류 시 상태 롤백 가능 |

### 생성 파이프라인 구조 (7단계)

Analyze → Design → Implement → Plan Tests → Write Tests → Document → Publish (+ Refine 반복)

검증 수치: GIMP, Blender 등 8개 프로덕션 애플리케이션 대상 1,298개 테스트 통과.

## 2. 이 책의 harness 정의와 교차/차이 비교표

| 비교 항목 | CLI-Anything HARNESS.md | 이 책의 harness 정의 |
|----------|------------------------|----------------------|
| **개념 초점** | 대상 소프트웨어(환경)를 에이전트 언어로 변환하는 어댑터 | 에이전트 runtime에 AgentOps를 점진적으로 주입하는 operational envelope |
| **적용 타겟** | 개별 GUI 소프트웨어 (GIMP, Blender 등) | 에이전트 프로세스 전체 (메모리, 자원, 스케줄러, 관찰) |
| **상태 관리 주체** | harness 인스턴스 (REPL 세션 내 상태 기계) | harness + Watchdog 조합 (프로세스 경계에서 관리) |
| **결정론성 달성 방법** | JSON 출력 강제 + 상태 모델 추상화 | 자원 경계(RSS/CPU 상한) + 재현 가능한 게이트 통과 기준 |
| **점진성 원칙** | `refine` 명령으로 비파괴적 CLI 커버리지 확장 | 6-Gate 단계적 통과 (Fieldkit 점진적 원칙) |
| **핵심 문제 의식** | GUI → CLI 번역의 인지 오버헤드 | harness=None 상태에서의 자원 고갈·상태 오염 |

### 교차점 (두 정의가 수렴하는 지점)

1. **결정론성:** 양쪽 모두 에이전트 실행 레이어에서 확률적 LLM의 한계를 구조로 보완해야 한다는 결론 도달.
2. **점진성:** "한 번에 완성하지 않는다" — CLI-Anything의 `refine` 반복과 이 책의 Fieldkit 점진적 원칙은 동일한 설계 철학의 독립 표현.
3. **관찰 가능성:** JSON 출력 (CLI-Anything) / heartbeat + 로그 강제 (이 책) — 표현이 다르지만 "harness가 에이전트 상태를 외부에서 읽을 수 있어야 한다"는 전제 공유.

### 차이점 (두 정의가 갈라지는 지점)

1. **방향:** CLI-Anything은 환경→에이전트 방향(환경을 에이전트 친화적으로 변환). 이 책은 에이전트→환경 방향(에이전트를 안정적으로 운용하기 위한 operational wrapper).
2. **범위:** CLI-Anything harness는 특정 소프트웨어 인터페이스에 한정. 이 책의 harness는 에이전트 런타임 전체(메모리, 자원, 보안, 복원력) 포함.
3. **실패 대응:** CLI-Anything은 Undo/Redo로 명령 레벨 롤백. 이 책은 Watchdog으로 프로세스 레벨 재시작.

## 3. 독립 수렴의 의미

**수렴 구조:** HKUDS(소프트웨어 인터페이스 연구)와 이 책의 저자(1인 에이전트 운용)가 서로 다른 출발점에서 "harness"라는 개념에 독립적으로 도달.

| 항목 | HKUDS CLI-Anything | 이 책 저자 |
|------|-------------------|-----------|
| 출발 문제 | GUI 소프트웨어가 에이전트에게 불투명함 | 단일 에이전트가 장기 운용 중 자원 고갈로 붕괴 |
| 도달 개념 | 에이전트 친화적 어댑터 레이어 | 에이전트 안정 운용을 위한 operational envelope |
| 공통 결론 | 에이전트와 환경 사이에는 구조적 중간 레이어가 필요하다 | |
| 개발 시점 | 2025–2026 (독립 병렬) | 2025–2026 (독립 병렬) |

**이 수렴이 증거로 기능하는 방식:** 두 팀이 서로를 모르는 상태에서 동일한 문제 구조(에이전트와 환경 사이의 불일치)를 발견하고 유사한 해법(중간 어댑터 레이어)에 도달했다는 사실은, 이 책의 harness 개념이 저자 1인의 특수 경험에서 비롯된 것이 아니라 2025–2026 에이전트 운용 현실에서 독립적으로 반복 발견되는 패턴임을 시사.

**한계:** CLI-Anything은 소프트웨어 인터페이스 레이어에 집중하고 에이전트 런타임 안정성(자원, 복원력)은 다루지 않음. 이 책의 harness 정의가 더 넓은 범위를 포함. 수렴은 "중간 레이어 필요성"에 한정되며, 구현 범위 전체에 걸친 수렴은 아님.
