## 작성 규칙

### 목표 문체: 서울대·KAIST급 이공계 교수 텍스트북

현장에서 실패를 관찰한 실무자가 쓴 실험 기록. 블로그도 강의록도 아니다.
인과 구조가 문장 안에 내장되어 있고, 독자를 설득하려 하지 않고 분석을 전개한다.

### 문장 구조 원칙

- 긴 문장은 복잡한 인과 관계를 한 문장 안에 담기 위해 쓴다. 수식을 위해 쓰지 않는다.
- 문단은 **관찰 → 분석 → 한계(또는 다음 질문)** 순서로 움직인다. 명시적 전환 없이.
- 주어가 이미 문맥으로 명확하면 반복하지 않는다.
- 수치는 강조 없이 문장 안에 녹는다.
- 단정과 유보를 구분한다: "~이었다"(관찰 사실) / "~것으로 보인다"(추론) / "~일 수 있다"(가능성). 세 단계를 섞지 않는다.

### 구조

- 섹션 시작: 독자가 따라올 문제 구조를 제시한다. "핵심 메시지 한 문장" 공식을 쓰지 않는다.
- 전개: 관찰 → 측정 결과 → 분석 → 이 분석이 성립하지 않는 조건.
- 실험 인용: "E14에서 관찰한 바에 따르면" + 구체적 수치.
- Dispatch 인용: "FD-001 MiroFish의 등장은..."
- 5변수 참조: "이 실패의 1차 병목은 [변수명]이었다."
- 스냅샷 마커: "2026년 3월 기준으로"
- 섹션 끝: 다음 섹션으로의 전환을 메타 언급 없이 자연스럽게 닫는다.

### AI 문체 8대 금지 — 작성 완료 후 반드시 self-check

작성 완료 후, 아래 증상이 있으면 해당 문장을 고치고 출력한다.

1. **단문 나열**: 짧은 독립 문장이 3개 이상 연속되는가?
   - "A였다. B였다. C였다." → 인과를 연결한 하나의 문장으로.

2. **번호 나열**: "첫째", "둘째", "셋째"가 있는가?
   - 리스트가 아니라 문장 안의 흐름으로 전환한다.

3. **설교조 종결**: "~이 중요하다", "~해야 한다", "~임을 알 수 있다"가 있는가?
   - 없앤다. 관찰이 결론을 만들면 선언이 필요 없다.

4. **괄호 설명 남발**: 이미 소개된 용어에 다시 괄호 설명이 붙어 있는가?
   - 처음 한 번 이후에는 그냥 쓴다.

5. **메타 전환 어구**: "이처럼", "위에서 살펴본 바와 같이", "다음으로는 ~을 살펴보겠다"가 있는가?
   - 전부 없앤다. 논리가 흐르면 전환 어구가 필요 없다.

6. **동일 주어 반복**: 같은 주어가 연속 3문장 이상 등장하는가?
   - 합치거나 주어를 생략한다.

7. **선언형 결론**: 마지막 문장이 "따라서 X가 필요하다/중요하다/확인되었다"인가?
   - 관찰이 결론을 만든다. 결론을 다시 선언하지 않는다.

8. **대칭 반복**: "A는 B이다. C는 D이다. E는 F이다." 구조가 3회 이상 반복되는가?
   - 두 번째부터는 대비나 긴장이 있어야 한다.

### 내용 금지

- hype 금지: "혁신적", "패러다임 전환", "unprecedented"
- 수치 없는 성능 서술 금지: "성능이 떨어졌다" → "tool call 성공률이 87%에서 54%로"
- DR 요약본을 직접 인용하지 않는다: DR이 인용한 원문을 찾아 인용한다.
