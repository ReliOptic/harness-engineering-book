# /learn [chNN] "[개념명]"

Claude 웹에서 공부한 내용을 책의 학습 기록(Learning Note)으로 정리하고 저장한다.

## 왜 이 스킬이 필요한가

저자가 개념을 하나하나 익혀가는 과정 자체가 이 책의 재료다. 전문가의 완성된 설명이 아니라, **이해의 과정** — 처음에 무엇이 헷갈렸고, 어떤 비유나 사례가 이해를 열었고, 아직 무엇이 불확실한가 — 이 기록이 독자에게도 동일한 이해의 경로를 제공한다.

## 실행 단계

1. 사용자에게 아래 정보를 묻는다:
   - **무엇을 공부했는가**: 개념명, 주제
   - **출발점**: 공부하기 전에 어떻게 이해하고 있었는가 (오해 포함)
   - **전환점**: 어떤 설명/비유/사례가 이해를 바꿨는가
   - **현재 이해**: 지금은 어떻게 설명할 수 있는가 (자기 말로)
   - **아직 불확실한 것**: 아직 해소되지 않은 질문

2. `glossary.md`에서 해당 개념이 이미 정의되어 있는지 확인한다.
   - 있으면: 기존 정의와 사용자의 현재 이해를 비교하여 정합성을 확인한다.
   - 없으면: glossary 추가 후보로 표시한다.

3. `chapter-map.md`에서 이 개념이 어떤 챕터 어떤 섹션에 속하는지 확인한다.

4. Learning Note를 작성하여 저장한다.

5. 해당 챕터 파일에 `<!-- LN: [개념명] → evidence/learning-notes/LN-NNN.md -->` 주석을 삽입한다.

## Learning Note 형식

```markdown
# LN-NNN: [개념명]

**Date:** YYYY-MM-DD
**Author:** Kiwon
**Target chapter:** Ch.N §M
**Related terms:** [glossary 용어들]

## 출발점 — 공부 전의 이해

[처음에 어떻게 알고 있었는가. 오해가 있었다면 그 오해도 기록한다.]

## 전환점 — 무엇이 이해를 바꿨는가

[구체적인 설명, 비유, 사례, 코드, 논문 등. 가능하면 원문을 인용한다.]

## 현재 이해 — 자기 말로

[지금 이 개념을 다른 사람에게 설명한다면. 이 책의 맥락에서.]

## 아직 불확실한 것

[해소되지 않은 질문. 이것이 다음 학습이나 실험의 출발점이 된다.]

## 책에 어떻게 반영할 것인가

[이 이해가 어떤 챕터의 어떤 문단을 바꾸거나 새로 쓰게 하는가.]

## Tags

`#변수명` `#챕터` `#개념`
```

## 저장 위치

`evidence/learning-notes/LN-NNN-[개념명].md`

> `evidence/learning-notes/` 디렉토리가 없으면 생성한다.

## 번호 부여

- `evidence/learning-notes/` 디렉토리의 기존 파일 중 가장 큰 번호 + 1
- 첫 번째 노트는 LN-001

## 작성 원칙

- **정직하게**: 모르는 것을 모른다고 쓴다. 이해하지 못한 채 넘어간 부분을 표시한다.
- **과정을 남긴다**: 최종 이해만이 아니라, 처음의 오해와 전환의 계기를 기록한다.
- **산업계 근거 우선**: 자체 조어보다 GitHub 프로젝트, 논문, SRE 문헌 등에서 이미 사용되는 표현을 찾아 쓴다. 새 용어가 필요하면 기존 개념의 조합임을 명시한다.
- **책의 분석 구조와 연결**: 5변수 프레임워크, 실패 예산 재할당, harness overhead 등 이 책의 분석 구조와 어떻게 연결되는지 기록한다.
- **실험으로 이어지게**: "아직 불확실한 것"이 E01-E22 중 하나와 연결되면 명시한다.

## 사용 예시

/learn ch03 "SRE error budget과 failure budget reallocation의 관계"
/learn ch07 "self-healing systems과 reflexion의 차이"
